# Self-Healing Tests · 测试修复台

**按钮没坏，测试红了。修定位器，保留真正要检查的事。**

页面把 `save-user` 改名为 `save-profile`，保存功能还好好的，旧测试却找不到按钮。
测试修复台把这次失败、建议修改的一行代码和重新运行的输出放在一起。你先看 diff，再决定应用；测试真的通过，界面才显示复验成功。

![一行定位器补丁与真实复验结果，保存成功的断言保持不变](docs/images/verified-repair.png)

### 绿灯之外，还要知道改了什么

写 Playwright 的人都遇到过这种维护问题。这个工作台适合演示和讨论自动修复流程：怎样识别失效定位器，怎样让人审阅补丁，以及怎样避免为了“修绿”而删掉断言。

这里的修复建议来自已知样例的规则，没有模型推理。**浏览器运行、源码修改和退出码是真实的；目前只修这一种定位器改名。**

### 在本机打开

准备 **Node.js 24 LTS** 与 npm（也支持 22.12+ 的 22 系列及 26+；不支持 23/25），然后运行：

```sh
git clone https://github.com/shenyangs/self-healing-tests.git
cd self-healing-tests
npm run setup
npm run doctor
npm run dev
```

浏览器打开 [http://127.0.0.1:4210](http://127.0.0.1:4210)，终端保持运行；结束时按 Ctrl+C。首次 setup 会联网安装依赖与测试浏览器，下载时间取决于网络。安装问题见 [使用手册](docs/usage.md)。

### 从一次失败，走到可核对的通过

1. 点击 **运行失败测试**：浏览器打开 V2 页面，旧定位器超时，输出区显示失败日志。
2. 点击 **获取修复建议**：检查“保存资料”按钮后，中央显示将 `save-user` 改为 `save-profile` 的一行 diff。
3. 审阅后点击 **应用并重新验证**：修改测试文件，重新执行；退出码为 0 才显示 **复验通过**。

![运行前的修复工作台：操作列表、测试源码与运行输出区](docs/images/workbench.png)

紧接着的 `toHaveText('保存成功')` 断言始终保留。完整输出、源码差异、截图、视频和 trace 位于 `artifacts/red/` 与 `artifacts/green/`。再点第一步，会恢复旧测试、重新开始；每次重跑会覆盖上次证据。

### 可以修什么，不能替你判断什么

只允许改内置 `fixtures/tests/save.spec.ts` 的已知定位器，不接受更改断言、跳过测试或写其他路径。它不能修复任意测试，也不运行模型生成的代码。

当前为单个本地工作流，不支持多人并发；后端重启后要从第一步开始。样例保存只更新页面状态，没有数据库。这个小例子验证的是定位器修复过程，不代表所有测试失败都应该自动修复。
